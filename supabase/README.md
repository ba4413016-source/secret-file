# طبقة البيانات المحلية

هذه المجلدات تحتوي ترحيل PostgreSQL أوليًا وبيانات تطوير خيالية. لا ينشئ الإعداد مشروع Supabase سحابيًا، ولا يربط المستودع بمشروع خارجي، ولا يضم مفاتيح أو كلمات مرور.

## تشغيل محليًا لاحقًا

بعد تثبيت Docker وSupabase CLI على جهاز التطوير:

```sh
supabase start
supabase db reset
```

`supabase db reset` يعيد إنشاء قاعدة التطوير محليًا، ويطبّق ملفات `migrations/` ثم يحمّل `seed.sql`. لا تشغّل أمرًا يستهدف مشروعًا سحابيًا لهذا الغرض. لا يتضمن المستودع إعداد نشر أو مشروعًا مربوطًا.

## المصادقة

- يعتمد الحساب على Supabase Auth؛ المفتاح الأساسي في `public.users.id` مرجعه `auth.users.id`. لا تُنسخ عناوين البريد أو كلمات المرور إلى `public`.
- ينشئ trigger ملفًا عامًا افتراضيًا بمعرّف مستخدم واسم عرض غير حساس. لا يقرأ بيانات metadata التي يقدمها المستخدم لمنح رتبة أو توثيق أو XP.
- إعداد التطوير يطلب تأكيد البريد، يمنع الحساب المجهول، يستخدم مدة JWT قصيرة نسبيًا وتدوير refresh tokens. يتيح Supabase Auth تسجيل البريد وكلمة المرور وOTP/Magic Link؛ مزود Google يحتاج تهيئة منفصلة بمفاتيح محفوظة خارج المستودع.
- لا يوجد حساب `admin` مضمّن في seed. لا تجعل حسابًا إداريًا عبر metadata أو استدعاء عميل؛ تهيئة أول مسؤول يجب أن تتم مرة واحدة عبر قناة تشغيل موثوقة على الخادم، مع أسرار في مخزن أسرار، وبعد التحقق من هوية المالك. لا يُرسل `service_role` أو أي مفتاح سري إلى المتصفح.

## حدود التفويض

- كل جدول في `public` الذي يعرّضه Data API مفعّل عليه RLS، مع سحب منح `anon` و`authenticated` أولًا ثم منح أقل الصلاحيات اللازمة.
- سياسات الصفوف تحدّ من قراءة الملفات الشخصية، وتحصر بيانات الملاحظات والتقدم والرسائل والإشعارات بمالكها أو أطراف المحادثة. المحتوى العام للقضايا لا يظهر إلا إذا كان منشورًا؛ الحل منفصل ولا يقرأه اللاعب إلا بعد إكمال القضية.
- الأدوار والتوثيق والرتب وXP والنتائج ومكافآت المستخدم وسجلات التدقيق ليست قابلة للتعديل من العميل. تقدّم اللعب الذي يكتبه العميل يقتصر على `current_stage` و`client_state`؛ اعتماد النتيجة النهائية يحتاج خدمة خادم موثوقة.
- المحادثات تُنشأ من جهة خادم موثوقة بعد قبول الطلب. الرسائل محصورة بالمشاركين النشطين، ولا تُرسل المرفقات في هذه المرحلة. يرفض trigger الرسالة رقم 51 للمستخدم في اليوم UTC بعد قفل معاملاتي ينسّق الطلبات المتزامنة.
- إعداد Storage buckets وسياساتها وRealtime وEdge Functions وعمليات اعتماد النتائج غير مضمنة في هذه الدفعة؛ لا تعتبر `storage_path` رابطًا عامًا.

## ملفات المصدر

- `config.toml`: إعداد محلي للـ CLI ومصادقة التطوير فقط.
- `migrations/20261121150000_initial_data_layer.sql`: الأنواع والجداول والفهارس والـ triggers والمنح وسياسات RLS.
- `seed.sql`: قضايا وشخصيات وأدلة وحلول وشارات وتحدٍ خيالي؛ لا ينشئ مستخدمين أو بيانات اعتماد.
- `../docs/SCHEMA.md`: خريطة الجداول وسلوك التفويض المقصود.
